Here's the layered picture, grounded in what's actually in this repo.

## 1. Live, whole-GPU engine activity — `amd-smi`

```bash
amd-smi metric -u              # engine usage (GFX / UMC / MM)
amd-smi metric -u -w 1         # watch, 1s interval
amd-smi monitor -u -m -n -d    # gfx / mem / encoder / decoder util + clocks
```

Flags are defined in amdsmi_parser.py (`-u, --usage`) and amdsmi_parser.py (`-u, --gfx` for `monitor`).

Backing struct in amdsmi.h — `amdsmi_engine_usage_t { gfx_activity; umc_activity; mm_activity; }` via `amdsmi_get_gpu_activity()`.

For MI300-class per-XCD / per-partition breakdown, `amdsmi_get_gpu_metrics_info()` fills amdsmi.h: `gfx_busy_inst[XCC]`, `gfx_busy_acc[XCC]`, `vcn_busy[]`, `jpeg_busy[]`.

Quick sysfs equivalent: `cat /sys/class/drm/card*/device/gpu_busy_percent`.

## 2. Per-process CU occupancy + SDMA — `amd-smi process`

```bash
amd-smi process -e             # all engine usages per PID
```

Output columns include `CU %` and `SDMA` (amdsmi_logger.py). Fields: `cu_occupancy` (percent) and `sdma_usage` (microseconds) — amdsmi.h. This is the only place SDMA busy is directly exposed as a number.

## 3. Per-kernel hardware counters — `rocprofv3`

Discover what your ASIC supports first:

```bash
rocprofv3 --list-avail
rocprofv3-avail list --pmc -d 0
rocprofv3-avail pmc-check SQ_WAVES GRBM_GUI_ACTIVE    # do they fit one pass?
```

Counter definitions live in basic_counters.xml and derived_counters.xml.

| Engine                        | Counters                                                                                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Whole GPU busy                | `GRBM_GUI_ACTIVE`, `GRBM_COUNT`, `GPUBusy`                                                                                                                 |
| Wavefronts / occupancy        | `SQ_WAVES`, `SQ_LEVEL_WAVES`, `SQ_ACCUM_PREV_HIRES`, `SQ_BUSY_CYCLES`, `SQ_BUSY_CU_CYCLES`, `Wavefronts`, `MeanOccupancyPerCU`, `MeanOccupancyPerActiveCU` |
| CP (command processor)        | `CPC_CPC_STAT_BUSY`, `CPC_CPC_STAT_IDLE`, `CPC_CPC_STAT_STALL`, `CPF_CMP_UTCL1_STALL_ON_TRANSLATION`                                                       |
| SPI (wave launch into WGP/CU) | `SPI_CSN_BUSY`, `SPI_CSN_WAVE`, `SPI_CSN_NUM_THREADGROUPS`, `SPI_CSN_WINDOW_VALID`                                                                         |
| ALU / MFMA                    | `VALUBusy`, `SALUBusy`, `VALUUtilization`, `MfmaUtil`                                                                                                      |
| Memory / L2                   | `MemUnitBusy`, `MemUnitStalled`, `L2CacheHit`, `FETCH_SIZE`, `WRITE_SIZE`, `TCC_HIT_sum`, `TCC_MISS_sum`                                                   |

```bash
# occupancy + CP + SPI, split into passes so each group fits in one pass
rocprofv3 --pmc GRBM_GUI_ACTIVE SQ_WAVES SQ_BUSY_CYCLES SQ_ACCUM_PREV_HIRES SQ_LEVEL_WAVES \
          --pmc MeanOccupancyPerCU MeanOccupancyPerActiveCU \
          --pmc CPC_CPC_STAT_BUSY CPC_CPC_STAT_IDLE CPC_CPC_STAT_STALL \
          --pmc SPI_CSN_BUSY SPI_CSN_WAVE SPI_CSN_NUM_THREADGROUPS \
          --output-format csv -- ./your_app
```

Results land in `pmc_1/`, `pmc_2/`, … as `counter_collection.csv`. Docs: using-rocprofv3.rst.

**SDMA has no PMC block in rocprofv3** — use `rocprofv3 --memory-copy-trace --stats` instead to get per-copy SDMA engine timings.

## 4. Per-SE / SA / WGP granularity — perf-dkms

This is the only component here that gives WGP-level occupancy, exposed as a Linux perf PMU:

```bash
sudo insmod build/src/amdgpu_pmu.ko
ls /sys/bus/event_source/devices/amdgpu_pmu/events/

perf stat -e amdgpu_pmu/sq_waves,se=0/ -a sleep 1              # per shader engine
perf stat -e amdgpu_pmu/sq_waves,se=1,sa=0/ -a sleep 1         # per shader array
perf stat -e amdgpu_pmu/sq_waves,se=2,sa=1,wgp=3/ -a sleep 1   # per WGP
perf stat -e amdgpu_pmu/cpc_busy/ -a sleep 1                   # CP busy
perf stat -e amdgpu_pmu/cpc_stall/ -a sleep 1
```

Full dimension syntax `amdgpu_pmu/COUNTER,xcc=X,se=N,sa=M,wgp=P,cu=C/` is documented in user_guide_dimensions.md. Comparing `sq_waves` across `se=0..3` is the standard way to spot load imbalance across shader engines.

## Practical recipe

1. `amd-smi monitor -u -m -w 1` → is the GPU busy at all, and which engine?
2. `amd-smi process -e` → which PID owns the CU occupancy / SDMA time?
3. `rocprofv3 --pmc MeanOccupancyPerActiveCU VALUBusy MfmaUtil MemUnitBusy MemUnitStalled -- ./app` → per-kernel: occupancy-bound vs ALU-bound vs memory-bound.
4. `perf stat -e amdgpu_pmu/sq_waves,se=N/` → per-SE/WGP imbalance, if step 3 shows low occupancy with no obvious stall.
